# Contributing to ClipStack

Thanks for taking an interest! ClipStack is a small, opinionated tool, and
contributions of all sizes are welcome — bug fixes, platform knowledge,
documentation, and ideas.

## Before you start

- Read the [user README](README.md) to understand the product, and
  [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for the toolchain, repo layout,
  and how to run the app.
- For anything larger than a typo fix, open an issue first to discuss the
  change before writing code. This avoids wasted effort on directions the
  project won't take.

## Design constraints

These are the product's core opinions — changes that break them are unlikely
to be accepted, so please discuss first:

- **Never intercept Cmd+C or Cmd+V.** Capture is polling-based
  (`NSPasteboard.changeCount`); the picker shortcut is the only global
  hotkey, and it is rebindable.
- **macOS only.** The paste-injection and pasteboard layers are AppKit and
  Core Graphics by design; cross-platform abstractions are out of scope.
- **Privacy-preserving capture.** Content advertising
  `org.nspasteboard.ConcealedType`, `TransientType`, or `AutoGeneratedType`
  is never recorded, and the *Never capture from* exclusion list must keep
  working.
- **Lazy file entries.** Files are stored as URL references, never as copies
  of their contents.
- **No Dock icon, no always-on window.** ClipStack is an accessory
  (`LSUIElement`) menu-bar app; the picker is a panel that appears on demand.

## Making a change

1. Fork the repository and create a branch off `main`, named after what it
   does, e.g. `fix/picker-focus-after-hide` or `feat/export-stack`.
2. Run the app while developing:

   ```sh
   npm install
   npm run tauri dev
   ```

   Remember that each rebuild gets a new ad-hoc signature, so Accessibility
   may need to be re-granted (see the README troubleshooting note).
3. Keep the webviews type-safe: `npx tsc --noEmit` must pass, and Rust must
   build without new warnings (`cargo check` in `src-tauri/`).
4. If you touched the Rust command surface, update the typed wrappers in
   `src/lib/ipc.ts` so the two sides stay in sync.
5. If you changed behaviour users see, update the README (settings table,
   shortcuts, troubleshooting) accordingly.

## Commit style

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: pin entries so they cannot be evicted
fix(picker): keep the window key when the app is an accessory
docs: explain the lazy-copy behaviour for file entries
```

Scope when it helps (`picker`, `paste`, `store`, `ci`, …). One logical change
per commit.

## Opening a pull request

- Fill in the PR template: what changes, why, and how it was tested.
- Link the issue you are addressing (`Closes #123`).
- Include a screenshot or short recording for picker/settings UI changes.
- Keep PRs focused; split unrelated changes.

A maintainer will review and merge. Don't worry about version numbers or
tags — releases are cut by the maintainer with the scripts in `scripts/`.

## Reporting problems

For bugs, include: macOS version, ClipStack version (bottom of Settings),
what you copied, what you expected, and what happened. If paste misbehaves,
also mention whether Accessibility is granted (Settings shows the real
state) and whether the problem appeared after a rebuild/update.
